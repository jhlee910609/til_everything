- **전시 영역 번들 사이즈 개선 (2022.06 ~ 2022.12)**
  - **문제**
    - 거대한 레거시 코드와 라이브러리(Moment.js 등)로 인한 번들 크기 과다.
    - 무분별한 dynamic import로 사용 유/무 판단이 어려운 컴포넌트 다수 존재.
    - 미사용 페이지 추적 불가(기획 히스토리 이슈).
  - **해결**:
    - 라이브러리 교체(`Moment.js` → `Day.js`, `lodash` → `lodash/es` ) 및 **미사용 코드(Dead Code) 제거**, **적절한 상황에서의 Dynamic Import** 적용.
    - 전시 기획자와 불필요한 전시 페이지 및 레거시 컴포넌트 정리로 공용 모듈 용량 최적화.
  - **성과**:
    - PC 번들 사이즈 **53%**, 모바일 **24%** 감소 (64MB → 29MB).
    - 사내 공용 모듈 용량 **32% 절감**.
    - 전시 기획/개발 간의 히스토리 정리.

- **협력사 레거시 코드 개선 및 컴포넌트 시스템 고도화**
  - **문제**: **Raw HTML 복사/붙여넣기 코드**가 산재하고, 복잡한 가격 계산 로직이 테스트 없이 방치되어 유지보수가 어려움.
  - **해결**:
    - **UI/로직 분리**: 중복 마크업을 퍼블리셔 및 협력사와 협업하여 **재사용 가능한 컴포넌트**로 표준화하고, 비즈니스 로직은 **Custom Hook**으로 분리하여 재사용성 증대.
    - **안정적 리팩토링**: 기존에 없던 **단위 테스트(Unit Test)** 환경을 구축하여 가격 계산 등 핵심 로직을 문제 없이 리팩토링.
  - **성과**: 기술 부채 해소 및 유지보수 효율성 증대, 결제 로직 무장애 리팩토링 달성.

- **검색 개발팀 지원 및 검색 사용성 및 performance 개선 (6개월)**
  - **검색 필터 렌더링 성능 최적화**
    - **문제**: 모바일 디바이스에서 검색 필터 진입 시 `DOM` 개수 과다로 인한 렌더링 지연 발생 (`visibility` 속성 제어 방식).
    - **해결**: 성능 이슈를 먼저 발굴하여(Issue Raising) 퍼블리셔와 **Bottom-up** 방식으로 협업 제안. `DOM`을 조건부(Attach/Detach)로 렌더링하도록 구조를 개선.
    - **성과**: 필터 초기 로딩 속도 **7% 단축** (1841ms → 1711ms).
  - **검색어 API 호출 최적화 및 비동기 제어**
    - **문제**: 검색어 입력 시 **Debounce 미적용**으로 인한 과도한 API 호출 및 동일 키워드 중복 요청으로 리소스 낭비 발생.
    - **해결**:
      - **Debounce** 도입으로 연속된 입력에 대한 불필요한 API 호출 차단.
      - **React-Query 캐싱**을 활용하여 이미 조회한 키워드에 대한 중복 요청(Refetch) 방지.
      - **AbortController**를 적용해 이전 요청을 취소하여 경쟁 상태(Race Condition) 해결.
    - **성과**: 불필요한 네트워크 트래픽 절감 및 안정적인 검색 결과 제공.

- **AI 툴 활용 및 사내 도구 개발을 통한 DX(개발자 경험) 개선**
  - **Cursor AI 도입**: 팀 내 도입 주도 및 전용 컨벤션 룰셋 배포로 코드 작성 효율 증대 (사내 베스트 프랙티스 선정).
  - **전시 관리 대시보드(Bigbro) 개발**: 전시 데이터 시각화를 통해 불필요한 매장 정리 등 데이터 기반 의사결정 지원 및 운영 생산성 증대.

  - **설계**: 사용자 요금제(Free/Pro/Enterprise)와 권한을 관리하는 아키텍처 및 **HOC / Wrapper Component** 패턴 활용으로 확장 가능한 제어 로직 구현.

- **React.js 도입 및 모던 아키텍처 도입 (2020.02 ~ 2022.02)**
  - **문제**: **Vanilla JS** 환경의 낮은 재사용성과 생산성 저하 문제 직면.
  - **해결**:
    - **점진적 마이그레이션**: **HOC/Wrapper 패턴**을 고안하여 **Vanilla JS와 React 컴포넌트 간의 양방향 호환성**을 확보, 서비스 중단 없는 점진적 전환을 주도.
    - '요소 검사 패널' **PoC(기술 검증)** 수행으로 기존 **Vanilla JS** 환경에 **React** 도입 제안 및 안정성 입증.
    - **사내 세미나** 및 **코딩 컨벤션** 구축을 통해 팀 내 기술 장벽 해소 및 마이그레이션 리딩.
  - **성과**: 캔버스 엔진 외 **전사 웹 서비스 영역(에디터 UI, 대시보드 등) 100% React 전환** 완료 및 개발 문화 혁신.

- **CSS 테마 시스템 고도화 및 렌더링 성능 개선**
  - **문제**: SCSS 파일 교체 방식의 한계로 실시간 테마 변경이 불가능하고, 번들 용량이 비대해지는 비효율 존재.
  - **해결**: **CSS Global Variables**를 도입하여 런타임 제어가 가능한 구조로 개선하고 CSS Modules 호환성 확보.
  - **성과**: 테마 전환 렌더링 속도 **약 6배 단축** (241.7ms → 41.25ms).

- [**템플릿 페이지 SEO 및 성능 최적화 (2020.08 ~ 2020.11)**](https://www.miricanvas.com/ko/templates?from=gnb)
  - **문제**: SPA 구조로 인한 크롤링 불가 문제와 고해상도 이미지 로딩 지연(11초 이상).
  - **해결**: **Prerendering** 제안 및 react-helmet을 활용한 메타 데이터 주입, Intersection Observer 기반 **Lazy Loading** 전면 적용.
