# execution context

> javascript의 근본, 핵심원리인 execution context (실행 컨텍스트)를 정리합니다.

## execution context란?

> 실행 컨텍스트는 **"코드가 실행되기 위해 필요한 환경"** 입니다. JavaScript 엔진이 코드를 실행할 때, 이 코드에 대한 정보를 담는 특별한 환경을 만드는데, 이것이 바로 실행 컨텍스트입니다.

JavaScript 엔진은 코드를 실행하기 위해 여러 정보를 필요로 합니다. 예를 들어, 변수는 어디에 저장되어 있는지, 함수 선언은 어떻게 되어 있는지, `this`는 무엇을 가리키는지 등을 알아야 합니다. 실행 컨텍스트는 이러한 정보들을 담고 있는 추상적인 공간이라고 생각할 수 있습니다.

실행 컨텍스트는 다음과 같은 세 가지 유형의 코드가 실행될 때 생성됩니다.

-   **전역 코드:** 스크립트가 처음 실행될 때 생성되는 **전역 실행 컨텍스트(Global Execution Context)** 입니다.
-   **함수 코드:** 함수가 호출될 때마다 생성되는 **함수 실행 컨텍스트(Function Execution Context)** 입니다.
-   **eval 코드:** `eval` 함수로 코드를 실행할 때 생성됩니다. (하지만 `eval`은 보안 및 성능 문제로 사용을 권장하지 않습니다!)

## 실행 컨텍스트 스택 (Execution Stack)

> JavaScript는 **단일 스레드(single-threaded)** 언어입니다. 즉, 한 번에 하나의 작업만 처리할 수 있습니다. 이를 위해 **실행 컨텍스트 스택(Execution Context Stack)**, 다른 말로 **콜 스택(Call Stack)** 이라는 자료구조를 사용합니다.

콜 스택은 LIFO(Last-In, First-Out) 구조로, 코드 실행 순서를 관리합니다.

1.  스크립트가 처음 실행되면, JavaScript 엔진은 **전역 실행 컨텍스트**를 생성하고 콜 스택에 넣습니다(push).
2.  함수가 호출되면, 해당 함수의 **함수 실행 컨텍스트**를 생성하여 콜 스택의 가장 위에 쌓습니다.
3.  함수 실행이 끝나면, 해당 함수의 실행 컨텍스트를 콜 스택에서 제거합니다(pop).
4.  모든 코드 실행이 끝나면, 전역 실행 컨텍스트도 스택에서 제거되고 프로그램이 종료됩니다.

```javascript
function first() {
  console.log("first!");
  second();
  console.log("first end!");
}

function second() {
  console.log("second!");
}

first();
// 1. first() 호출 -> first 실행 컨텍스트가 스택에 쌓임
// 2. console.log("first!") 실행
// 3. second() 호출 -> second 실행 컨텍스트가 스택에 쌓임
// 4. console.log("second!") 실행
// 5. second() 종료 -> second 실행 컨텍스트가 스택에서 제거됨
// 6. console.log("first end!") 실행
// 7. first() 종료 -> first 실행 컨텍스트가 스택에서 제거됨
```

## 실행 컨텍스트의 구성 요소

실행 컨텍스트는 크게 세 가지 주요 구성 요소로 이루어져 있습니다.

### 1. Lexical Environment (렉시컬 환경)

> 렉시컬 환경은 **"코드가 작성된 시점에서의 스코프 안에 있는 식별자(변수, 함수)와 그 값들을 기록하는 객체"** 입니다. 즉, 코드의 "문맥"을 정의합니다.

렉시컬 환경은 두 가지 주요 부분으로 구성됩니다.

-   **Environment Record (환경 레코드):** 현재 스코프 내의 `let`, `const`로 선언된 변수, 함수 선언 등을 기록하고 저장합니다. 이것이 바로 **호이스팅(Hoisting)** 과 직접적인 관련이 있는 부분입니다.
-   **Outer Environment Reference (외부 환경 참조):** 현재 스코프의 바깥쪽, 즉 상위 스코프의 렉시컬 환경을 참조합니다. 이를 통해 **스코프 체인(Scope Chain)** 이 구현되어, 현재 스코프에서 변수를 찾지 못하면 상위 스코프로 올라가며 변수를 찾을 수 있게 됩니다. 전역 렉시컬 환경의 외부 환경 참조는 `null`입니다.

### 2. Variable Environment (변수 환경)

`var`로 선언된 변수를 저장한다는 점을 제외하고는 렉시컬 환경과 거의 동일합니다. ES6 이전에는 렉시컬 환경과 변수 환경의 구분이 명확하지 않았지만, `let`과 `const`가 도입되면서 이 둘을 구분하게 되었습니다.

> **`let`/`const`와 `var`의 차이점:** `let`과 `const`는 렉시컬 환경에, `var`는 변수 환경에 저장됩니다. 이로 인해 `var`는 함수 레벨 스코프를, `let`/`const`는 블록 레벨 스코프를 가지게 되는 중요한 차이가 발생합니다.

### 3. `this` Binding

`this`가 가리키는 값이 결정됩니다. `this`는 함수 호출 방식에 따라 동적으로 결정되며, `strict mode`인지 아닌지에 따라서도 달라집니다.

## 실행 컨텍스트의 생성과 실행 과정

실행 컨텍스트는 **생성 단계(Creation Phase)** 와 **실행 단계(Execution Phase)** 두 단계로 나뉩니다.

### 1. 생성 단계 (Creation Phase)

코드가 실행되기 전에, JavaScript 엔진은 실행 컨텍스트를 생성하고 다음과 같은 작업을 수행합니다.

1.  **렉시컬/변수 환경 생성:** 스코프 내의 변수와 함수를 스캔하여 환경 레코드에 등록합니다.
2.  **호이스팅 발생:**
    -   **함수 선언:** 함수 전체가 메모리에 올라갑니다. (따라서 함수 선언문은 선언 전에 호출 가능)
    -   **`var` 변수:** `undefined`로 초기화되어 메모리에 올라갑니다. (선언 전에 사용하면 `undefined`)
    -   **`let`, `const` 변수:** 선언만 메모리에 올라가고 초기화되지 않습니다. 이 때문에 선언 전에 접근하면 **TDZ(Temporal Dead Zone)** 에 빠져 `ReferenceError`가 발생합니다.
3.  **`this` 값 결정:** `this`가 무엇을 가리킬지 결정됩니다.
4.  **스코프 체인 결정:** 외부 환경 참조(Outer Environment Reference)가 설정되어 상위 스코프와의 연결이 만들어집니다.

### 2. 실행 단계 (Execution Phase)

생성 단계가 끝나면, 코드를 위에서 아래로 한 줄씩 실행합니다.

-   변수에 값을 할당하고, 함수를 호출하는 등의 작업이 이 단계에서 이루어집니다.
-   만약 함수가 호출되면, 새로운 함수 실행 컨텍스트가 생성되어 콜 스택에 추가되고, 위 과정을 반복합니다.

## 정리

실행 컨텍스트는 JavaScript의 동작 원리를 이해하는 데 가장 중요한 핵심 개념입니다. 스코프, 호이스팅, `this`, 클로저 등 JavaScript의 주요 특징들이 모두 실행 컨텍스트를 기반으로 동작합니다. 이 개념을 잘 이해하면 코드의 동작을 예측하고, 디버깅하며, 더 나은 코드를 작성하는 데 큰 도움이 될 것입니다.
